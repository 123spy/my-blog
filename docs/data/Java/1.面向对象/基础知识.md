# 基础性知识

## 1. 抽象类（abstract class）与接口（interface）

### 1.1 核心定位一句话

- **抽象类**：表达“**是什么（is-a）**”的继承关系，适合承载**共享状态与通用实现**。
- **接口**：表达“**能做什么（can-do）**”的能力契约，适合定义**规范/扩展点**，支持**多实现**。

------

### 1.2 详细对比表（重点版）

| 对比维度      | 抽象类 abstract class                          | 接口 interface                                               |
| ------------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 继承/实现数量 | **单继承**：一个类只能 `extends` 一个抽象类    | **多实现**：一个类可 `implements` 多个接口                   |
| 成员变量      | 可有普通成员变量（实例字段），可维护**状态**   | 成员变量默认 `public static final`（常量），通常不存实例状态 |
| 方法类型      | 可有：抽象方法、普通方法、final 方法、静态方法 | 可有：抽象方法（默认 public）、`default` 方法、静态方法、私有方法（Java 9+） |
| 构造器        | **可以有构造器**（给子类初始化共享字段）       | **没有构造器**                                               |
| 访问修饰      | 方法/字段可用多种访问级别                      | 接口方法默认 `public`（抽象方法）；字段默认 `public static final` |
| 适用场景      | 需要共享代码 + 共享状态；模板方法模式          | 定义能力、规范；扩展点；解耦；策略/回调                      |
| 设计倾向      | “**强约束**” + “部分实现”                      | “**弱耦合**” + “组合能力”                                    |

------

### 1.3 什么时候选抽象类？什么时候选接口？

#### 优先选抽象类的情况

1. 你需要在父类中保存**状态**（字段），并让子类共享（例如：name、id、创建时间、通用缓存等）
2. 你需要提供一套**骨架实现**，强制子类只实现某些步骤（模板方法）
3. 类之间是明显的“同一类事物”的层级结构（is-a）

#### 优先选接口的情况

1. 你要定义的是“能力/规范”（比如：可比较 Comparable、可序列化 Serializable）
2. 一个类需要组合多种能力（多实现）
3. 你希望对外暴露的是契约，具体实现可以替换（面向接口编程）

------

### 1.4 代码示例：模板方法（抽象类强项）

```
abstract class DataProcessor {

    // 模板方法：定义流程，通常不希望子类改流程（可用 final）
    public final void process() {
        read();
        validate();
        transform();
        write();
    }

    protected abstract void read();       // 子类必须实现
    protected void validate() {           // 可选：提供默认校验
        System.out.println("default validate...");
    }
    protected abstract void transform();
    protected abstract void write();
}

class CsvProcessor extends DataProcessor {
    @Override protected void read() { System.out.println("read csv"); }
    @Override protected void transform() { System.out.println("transform csv"); }
    @Override protected void write() { System.out.println("write csv"); }
}
```

**要点**：抽象类适合把“**流程骨架**”固定下来，子类只负责填空。

------

### 1.5 代码示例：多能力组合（接口强项）

```
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

// 一个类实现多个接口：组合能力
class Duck implements Flyable, Swimmable {
    @Override public void fly() { System.out.println("duck flying"); }
    @Override public void swim() { System.out.println("duck swimming"); }
}
```

------

### 1.6 接口 default 方法：解决“加方法会破坏实现类”的问题

```
interface Logger {
    void log(String msg);

    default void info(String msg) {
        log("[INFO] " + msg);
    }

    static Logger ofConsole() {
        return System.out::println;
    }
}

class AppLogger implements Logger {
    @Override public void log(String msg) {
        System.out.println(msg);
    }
}
```

**要点**

- `default`：给接口提供默认实现，兼容历史实现类
- `static`：工具工厂方法（不依赖实现类）

------

### 1.7 常见面试/易错点总结

1. **接口变量**默认是 `public static final`，不能有实例字段。
2. **接口抽象方法**默认 `public`，实现时不能降低可见性。
3. 抽象类可以有构造器，接口没有构造器。
4. 一个类只能继承一个类（抽象类也一样），但可以实现多个接口。
5. Java 8+ 接口可以有 `default/static` 方法；Java 9+ 还可以有 `private` 方法用于复用逻辑。

## 2. 内部类（Inner Class）知识

### 2.1 内部类的分类

Java 常见内部类分四种：

1. **成员内部类**（非 static，写在类里作为成员）
2. **静态内部类**（static 修饰）
3. **局部内部类**（写在方法里）
4. **匿名内部类**（没有名字，通常用于一次性实现接口/继承类）

------

### 2.2 成员内部类（Member Inner Class）

#### 特点

- **依赖外部类对象**：必须先有外部类实例才能 new
- 能访问外部类所有成员（包括 private）
- 内部类对象隐含持有 `Outer.this` 引用

#### 示例

```
class Outer {
    private int x = 10;

    class Inner {
        void print() {
            System.out.println("x = " + x); // 访问外部类 private 成员
        }
    }
}

class Demo {
    public static void main(String[] args) {
        Outer outer = new Outer();
        Outer.Inner inner = outer.new Inner(); // 关键语法
        inner.print();
    }
}
```

#### 常见用途

- 内部类紧密依赖外部类状态（例如迭代器实现、组件内部结构）

------

### 2.3 静态内部类（Static Nested Class）

#### 特点

- **不依赖外部类实例**：可以直接 new
- 不能直接访问外部类实例成员（除非通过外部类对象）
- 更像是“写在类内部的普通类”，常用于封装/组织代码

#### 示例

```
class Outer {
    private int x = 10;
    private static int y = 20;

    static class StaticInner {
        void print() {
            System.out.println("y = " + y); // 只能直接访问外部类静态成员
            // System.out.println(x); // 编译错误：不能直接访问实例成员
        }
    }
}

class Demo2 {
    public static void main(String[] args) {
        Outer.StaticInner inner = new Outer.StaticInner(); // 直接 new
        inner.print();
    }
}
```

#### 常见用途（非常常见）

- Builder 模式：`User.Builder`
- 工具类内部的辅助类
- 避免成员内部类持有外部类引用导致内存泄漏

------

### 2.4 局部内部类（Local Inner Class）

#### 特点

- 定义在方法/代码块中，只在该作用域可见
- 可以访问外部类成员
- 可以访问方法中的局部变量，但该变量必须是 **final 或 effectively final**（“事实上是 final”）

#### 示例

```
class Outer {
    void run() {
        int base = 100; // effectively final：后续不再修改

        class LocalInner {
            void print() {
                System.out.println("base = " + base);
            }
        }

        new LocalInner().print();
        // base++; // 如果取消注释，base 不再 effectively final，会导致编译报错
    }
}
```

------

### 2.5 匿名内部类（Anonymous Inner Class）

#### 特点

- 没有类名，用一次就丢
- 常用于快速实现接口/继承抽象类
- Java 8+ 很多场景已被 **Lambda** 替代（如果是函数式接口）

#### 示例：实现接口（传统写法）

```
Runnable r = new Runnable() {
    @Override public void run() {
        System.out.println("running...");
    }
};
new Thread(r).start();
```

#### 同场景 Lambda（更简洁）

```
Runnable r = () -> System.out.println("running...");
new Thread(r).start();
```

------

### 2.6 内部类的一个“坑”：隐式引用导致内存泄漏

- **成员内部类**会默认持有外部类对象引用：`Outer.this`
- 如果内部类对象生命周期很长（例如被线程、静态集合持有），可能导致外部类无法被 GC

**规避建议**

- 如果不需要访问外部类实例成员，优先使用 **静态内部类**
- 或把内部类写成独立类

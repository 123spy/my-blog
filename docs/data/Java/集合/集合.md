# Java集合

## Collection(单列集合)

### List

 注：

List代表了有序可重复集合，可直接根据元素的索引来访问

此处的有序，代表的是。我插入的a c b，取出来的还是a c b。（正确）

容易误解：插入的a c b, 取出来是a b c。（错误）

#### ArrayList

**特点**

- 底层：动态数组
- 支持下标访问 `get(i)` 很快（O(1)）
- **尾部追加**快，**中间插入/删除**慢（要搬移元素）

**适用场景**

- 读多写少
- 需要频繁随机访问

扩容：

ArrayList都有一个初始容量（10），该容量代表了数组的大小。

每次到了需要扩容的时候，容器会扩容到目前的1.5倍

```java
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;

    // 新容量 = 旧容量 + 旧容量/2 （右移1位相当于除以2）
    int newCapacity = oldCapacity + (oldCapacity >> 1);

    // 如果新容量还是不够，直接使用minCapacity
    if (newCapacity - minCapacity < 0)
        newCapacity = minCapacity;

    // 如果新容量超过最大数组大小，调用hugeCapacity处理
    if (newCapacity - MAX_ARRAY_SIZE > 0)
        newCapacity = hugeCapacity(minCapacity);

    // 创建新数组并复制元素
    elementData = Arrays.copyOf(elementData, newCapacity);
}
```



#### LinkedList

**特点**

- 底层：双向链表
- **中间插入/删除**相对更合适（不搬移数组），但要先定位节点
- 随机访问慢（O(n)）
- 实现了List，Deque。可以用来实现队列与栈

**适用场景**

- 更偏“队列/栈”用法（头尾操作多）
- 需要频繁在头尾插入删除

#### Vector

**特点**

- 类似 ArrayList，但方法很多是 `synchronized`（线程安全）
- 性能通常不如 ArrayList

**建议**

- 现在大多不用 Vector
- 多线程更常用：`Collections.synchronizedList(...)` 或并发容器（如 CopyOnWriteArrayList）

### Set

注：

Set代表无序不可重复集合，只能根据元素本身来访问

TreeSet，Hash Set，LinkedHashSet就是各自用的对应的map，然后map的value都指向了同一个object。

所以对于null的支持情况也是一致的，HashSet与LinkedHashSet允许一个null，TreeSet则不允许。

对于TreeSet，LinkedHashSet是有序的，HashMap是无序的。

Queue是队列集合，同样有序

#### PriorityQueue

**特点**

- 底层：堆（最小堆默认）
- 每次 `poll()` 取出“优先级最高”的元素（默认最小）
- 插入/删除 O(log n)

**适用场景**

- TopK、调度、按优先级处理任务
- 中位数、合并多个有序流等经典题

## Map(双列集合)

注：

Map代表的是存储key-value对的集合，可根据元素的key来访问value。

对于TreeMap，LinkedHashMap是有序的，HashMap是无序的。

### HashMap

**特点**

- 底层：数组 + 链表/红黑树（JDK8 以后冲突严重会树化）
- 平均 O(1)
- 允许 `null` key（1个）和 `null` value（多个）
- 线程不安全

为什么允许null键，并且是1个那？

```java
// HashMap的put方法源码（JDK 1.8）
public V put(K key, V value) {
    // 重点：如果key是null，hash()方法会返回0
    return putVal(hash(key), key, value, false, true);
}

// hash方法源码
static final int hash(Object key) {
    int h;
    // 如果key == null，直接返回0
    // 否则才计算hashCode并扰动
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

为什么允许null值

```java
// HashMap对value没有任何限制
// 直接存储，不做任何检查
if (e != null) {  // e是旧值
    V oldValue = e.value;
    if (!onlyIfAbsent || oldValue == null)
        e.value = value;  // value可以是null
    afterNodeAccess(e);
    return oldValue;
}
```

扩容：

初始容量：16（默认）负载因子：0.75（默认）阈值 = 容量 × 负载因子

初始状态：HashMap只是一个数组，长度为16，负载因子是0.75，阈值是16 * 0.75 = 12

我们没插入一个k, v对，就会根据k计算出地址，然后将其插入进去。

如果此时计算出来的这个地址上已经有元素存放，采用拉链法解决。

将第一个已经插入该位置的元素作为链表头，向下延申。

如果HashMap的数组已经超过了阈值的大小，那么这个数组大小会翻倍，并重新计算全部的元素的位置，将其插入进去。

如果元素继续增多，出现了链表长度 > 8 且数组长度 ≥ 64

HashMap中的长度>8的那个链表转为红黑树。

如果后续通过不断删除，红黑树的大小<6了，这个红黑树就切换回链表

### TreeMap

**特点**

- 底层：红黑树
- 禁止null建，允许null值
- key 自动排序（自然顺序/Comparator）
- O(log n)
- 提供范围 API（非常强）：`floorKey/ceilingKey/subMap/headMap/tailMap`

**适用场景**

- 需要按 key 排序、做区间查询

为什么不允许null的键：因为它需要排序，但是null没有办法加入排序，所以才把null的key给禁止了

```java
// TreeMap的put方法源码分析
public V put(K key, V value) {
    Entry<K,V> t = root;
    
    // 关键：如果key为null，这里就崩溃了
    if (key == null)
        throw new NullPointerException(); // 直接抛异常
    
    // 需要比较key来找到插入位置
    Comparator<? super K> cpr = comparator;
    if (cpr != null) {
        // 用比较器比较，null无法比较
        cpr.compare(key, key); // null传进去就空指针
    } else {
        // 用自然排序，key必须实现Comparable
        // null无法调用compareTo方法
        ((Comparable<? super K>) key).compareTo((K)key);
    }
    // ...
}
```

### HashTable

**特点**

- 线程安全（synchronized）
- 底层是数组+链表
- **不允许 null key/value**。因为是古老设计，为了防止二义性，直接一刀切禁止掉
- 性能一般，设计老旧

**建议**

- 现在更常用 `ConcurrentHashMap`

### LinkedHashMap

**特点**

- 在 HashMap 上维护链表顺序
- LinkedHashMap = 双向链表 + HashMap
- 有两种模式
  - 插入模式：有put操作，就把元素插入到链表的最后
  - 访问模式：有get操作，就把元素插入到链表的最后


**适用场景**

- 需要可预测遍历顺序
- 想实现简单 LRU

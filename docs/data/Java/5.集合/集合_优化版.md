# Java 集合

## 一、集合体系总览

Java 集合大体分为两类：

- **Collection**：单列集合，存储一个个元素
  - `List`：有序、可重复
  - `Set`：不可重复
  - `Queue / Deque`：队列 / 双端队列
- **Map**：双列集合，存储 `key-value` 键值对

### 1.1 关于“有序”的说明

集合里的“有序”不一定是同一种含义，常见有以下几类：

- **插入顺序**：按元素放入的顺序遍历
- **排序顺序**：按自然顺序或比较器规则排序
- **出队顺序**：按 FIFO 或优先级规则取出

因此：

- `List` 的“有序”通常指**插入顺序**
- `LinkedHashMap` / `LinkedHashSet` 的“有序”通常指**插入顺序**
- `TreeMap` / `TreeSet` 的“有序”通常指**排序顺序**
- `Queue` 的“有序”通常指**出队顺序**
- `HashMap` / `HashSet` 通常是**遍历顺序不固定**

### 1.2 Collection 和 Collections 的区别

- `Collection`：单列集合顶层接口
- `Collections`：集合工具类，提供排序、查找、同步包装等静态方法

## 二、常见集合对比总表

| 集合 | 是否可重复 | 是否允许 `null` | 顺序特点 | 线程安全 |
|---|---|---|---|---|
| `ArrayList` | 可重复 | 允许 | 插入顺序 | 否 |
| `LinkedList` | 可重复 | 允许 | 插入顺序 | 否 |
| `Vector` | 可重复 | 允许 | 插入顺序 | 是 |
| `HashSet` | 不可重复 | 允许一个 | 遍历顺序不固定 | 否 |
| `LinkedHashSet` | 不可重复 | 允许一个 | 插入顺序 | 否 |
| `TreeSet` | 不可重复 | 通常不允许 | 排序顺序 | 否 |
| `PriorityQueue` | 可重复 | 不允许 | 按优先级出队 | 否 |
| `HashMap` | key 不可重复 | 1 个 `null` key，可多个 `null` value | 遍历顺序不固定 | 否 |
| `LinkedHashMap` | key 不可重复 | 同 `HashMap` | 插入顺序 / 访问顺序 | 否 |
| `TreeMap` | key 不可重复 | 不允许 `null` key，可允许 `null` value | key 排序 | 否 |
| `Hashtable` | key 不可重复 | 不允许 `null` key/value | 遍历顺序不固定 | 是 |

## 三、Collection（单列集合）

## 3.1 List

### List 的特点

- 有序：这里的“有序”指**插入顺序保留**
- 可重复
- 支持按索引访问

例如：

- 插入顺序是 `a c b`
- 取出来通常还是 `a c b`
- 这和“自动排成 `a b c`”不是一回事

---

### 3.1.1 ArrayList

**底层结构**

- 动态数组

**特点**

- 支持随机访问，`get(index)` 很快，时间复杂度约为 `O(1)`
- 尾部追加快
- 中间插入 / 删除慢，因为需要移动元素

**时间复杂度**

- 查询：`O(1)`
- 尾插：均摊 `O(1)`
- 中间插入 / 删除：`O(n)`

**扩容机制**

- 无参构造时，底层先是空数组
- 第一次添加元素时，通常扩容为默认容量 **10**
- 之后一般按 **1.5 倍**扩容

```java
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;

    // 新容量 = 旧容量 + 旧容量/2
    int newCapacity = oldCapacity + (oldCapacity >> 1);

    // 如果新容量仍然不够，直接使用 minCapacity
    if (newCapacity - minCapacity < 0)
        newCapacity = minCapacity;

    // 如果超过最大数组限制，则走 hugeCapacity
    if (newCapacity - MAX_ARRAY_SIZE > 0)
        newCapacity = hugeCapacity(minCapacity);

    elementData = Arrays.copyOf(elementData, newCapacity);
}
```

**适用场景**

- 读多写少
- 需要频繁随机访问

---

### 3.1.2 LinkedList

**底层结构**

- 双向链表

**特点**

- 随机访问慢，时间复杂度为 `O(n)`
- 头尾插入 / 删除更合适
- 中间插入 / 删除时，不需要像数组那样整体搬移元素
- 但如果按索引操作，通常还需要先遍历定位节点，因此实际不一定比 `ArrayList` 更快
- 实现了 `List`、`Deque`

**适用场景**

- 更偏队列 / 栈的用法
- 频繁做头尾插入删除

---

### 3.1.3 Vector

**特点**

- 类似 `ArrayList`
- 很多方法带有 `synchronized`，因此线程安全
- 性能通常不如 `ArrayList`

**建议**

- 现代开发中较少直接使用 `Vector`
- 多线程场景更常用：
  - `Collections.synchronizedList(...)`
  - `CopyOnWriteArrayList`

---

## 3.2 Set

### Set 的特点

- 不可重复
- 一般不支持通过索引访问
- 重点在于“判重”

### Set 的判重依据

- `HashSet` 判重依赖：`hashCode()` 和 `equals()`
- `TreeSet` 判重依赖：`compareTo()` 或 `Comparator.compare()`

注意：

- 如果重写了 `equals()`，通常也要重写 `hashCode()`
- 否则在基于哈希的集合中可能出现行为异常

### HashSet、LinkedHashSet、TreeSet 的关系

这三个 `Set` 的底层实现思路分别对应不同的 `Map`：

- `HashSet` 底层基于 `HashMap`
- `LinkedHashSet` 底层基于 `LinkedHashMap`
- `TreeSet` 底层基于 `TreeMap`

它们本质上都是“只使用 key，不关心 value”。

因此在 `null` 支持和顺序特点上，也和各自底层 `Map` 的性质高度一致：

- `HashSet`：允许一个 `null`，遍历顺序不固定
- `LinkedHashSet`：允许一个 `null`，保持插入顺序
- `TreeSet`：通常不允许 `null`，按排序规则有序

---

### 3.2.1 HashSet

**底层结构**

- 基于 `HashMap`

**特点**

- 元素不可重复
- 允许一个 `null`
- 遍历顺序不固定
- 查询、插入、删除平均时间复杂度约为 `O(1)`

**适用场景**

- 只关心判重
- 不要求遍历顺序

---

### 3.2.2 LinkedHashSet

**底层结构**

- 基于 `LinkedHashMap`

**特点**

- 元素不可重复
- 允许一个 `null`
- 保持插入顺序
- 相比 `HashSet` 多维护了一条双向链表

**适用场景**

- 既要判重，又希望遍历顺序可预测

---

### 3.2.3 TreeSet

**底层结构**

- 基于 `TreeMap`
- 底层是红黑树

**特点**

- 元素不可重复
- 通常不允许 `null`
- 自动排序
- 查询、插入、删除时间复杂度为 `O(log n)`

**为什么通常不允许 `null`**

因为 `TreeSet` 需要对元素进行比较排序，而 `null` 通常无法参与比较。

**适用场景**

- 需要去重并自动排序
- 需要范围查找

---

## 3.3 Queue / Deque

### Queue 的特点

- 队列通常遵循 **FIFO**：先进先出
- 它的“有序”更接近“出队顺序”
- 和 `List` 的插入顺序保留不是完全同一个概念

### Deque 的特点

- 双端队列，可从两端插入、删除
- 既可以当队列，也可以当栈

现代 Java 中：

- 实现栈时更推荐 `Deque` / `ArrayDeque`
- 一般不推荐继续使用老的 `Stack`

---

### 3.3.1 LinkedList

`LinkedList` 既能当 `List`，也能当 `Queue / Deque` 来用。

常见方法：

- 队列：`offer()` / `poll()` / `peek()`
- 双端队列：`addFirst()` / `addLast()` / `pollFirst()` / `pollLast()`

---

### 3.3.2 ArrayDeque

**底层结构**

- 循环数组

**特点**

- 头尾操作效率高
- 作为栈和普通队列时通常比 `LinkedList` 更推荐
- 不允许 `null`

**适用场景**

- 实现栈
- 实现普通队列
- 需要高效头尾操作

---

### 3.3.3 PriorityQueue

**底层结构**

- 堆
- 默认是最小堆

**特点**

- 每次 `poll()` 取出优先级最高的元素
- 默认情况下，数值最小的元素先出队
- 插入 / 删除时间复杂度为 `O(log n)`
- 不保证整体遍历有序，只保证堆顶优先级正确

**适用场景**

- TopK
- 任务调度
- 按优先级处理元素
- 合并多个有序流、中位数等经典题

---

## 四、Map（双列集合）

### Map 的特点

- 存储 `key-value` 键值对
- 通过 key 访问 value
- key 不可重复，value 可以重复

### Map 中“有序”的区别

- `HashMap`：遍历顺序不固定
- `LinkedHashMap`：按插入顺序或访问顺序遍历
- `TreeMap`：按 key 排序

### Map 中 key 判重依据

- `HashMap`：依赖 `hashCode()` 和 `equals()`
- `TreeMap`：依赖 `compareTo()` 或 `Comparator.compare()`

---

### 4.1 HashMap

**底层结构**

- `Node` 数组 + 链表 + 红黑树
- JDK 8 以后，哈希冲突严重时会树化

**特点**

- 平均时间复杂度约为 `O(1)`
- 允许 **1 个 `null` key**
- 允许 **多个 `null` value**
- 线程不安全

**为什么允许 `null` key**

因为 `HashMap` 对 `null` key 做了特殊处理：`hash(null)` 返回 0，因此可以统一落到某个桶中。

```java
public V put(K key, V value) {
    return putVal(hash(key), key, value, false, true);
}

static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

**为什么允许 `null` value**

因为 `HashMap` 对 value 本身没有做非空限制。

```java
if (e != null) {
    V oldValue = e.value;
    if (!onlyIfAbsent || oldValue == null)
        e.value = value;
    afterNodeAccess(e);
    return oldValue;
}
```

**扩容机制**

- 默认初始容量：`16`
- 默认负载因子：`0.75`
- 阈值：`容量 × 负载因子`
- 默认情况下阈值为：`16 × 0.75 = 12`

当元素个数超过阈值时：

- 数组容量通常扩为原来的 **2 倍**
- 需要重新分配元素位置

**哈希冲突处理**

当多个 key 计算后落到同一个桶时：

- 先以链表形式存储
- 当链表长度达到树化条件时，可能转换为红黑树

**树化条件（JDK 8 常见考点）**

- 当桶中链表长度 **>= 8**，并且数组容量 **>= 64** 时，可能树化为红黑树
- 当树中节点数 **<= 6** 时，可能退化回链表

**适用场景**

- 绝大多数普通键值映射场景
- 不要求顺序，追求较高查询效率

---

### 4.2 TreeMap

**底层结构**

- 红黑树

**特点**

- 不允许 `null` key
- 允许 `null` value
- key 会自动排序
- 查询、插入、删除时间复杂度为 `O(log n)`
- 提供范围查询 API：`floorKey()` / `ceilingKey()` / `subMap()` / `headMap()` / `tailMap()`

**适用场景**

- 需要按 key 排序
- 需要区间查询、范围查找

**为什么不允许 `null` key**

因为 `TreeMap` 插入元素时需要比较 key 来确定位置，而 `null` 通常无法参与比较。

```java
public V put(K key, V value) {
    Entry<K,V> t = root;

    if (key == null)
        throw new NullPointerException();

    Comparator<? super K> cpr = comparator;
    if (cpr != null) {
        cpr.compare(key, key);
    } else {
        ((Comparable<? super K>) key).compareTo((K) key);
    }
    // ...
}
```

---

### 4.3 Hashtable

**特点**

- 线程安全，很多方法带 `synchronized`
- 底层是数组 + 链表
- 不允许 `null` key 和 `null` value
- 设计较老，性能一般

**建议**

- 现代开发中更常用 `ConcurrentHashMap`

---

### 4.4 LinkedHashMap

**底层结构**

- `HashMap` + 双向链表

**特点**

- 在 `HashMap` 的基础上维护一条双向链表
- 可保持遍历顺序稳定
- 支持两种顺序模式：
  - **插入顺序**：按 put 的先后顺序遍历
  - **访问顺序**：元素被访问后，会被移动到链表尾部

**适用场景**

- 需要可预测遍历顺序
- 实现简单 LRU 缓存

---

## 五、线程安全集合补充

### 5.1 老式线程安全类

- `Vector`
- `Hashtable`

特点：

- 通过 `synchronized` 保证线程安全
- 设计较老，性能一般

### 5.2 更常见的现代选择

- `Collections.synchronizedList(...)`
- `Collections.synchronizedMap(...)`
- `CopyOnWriteArrayList`：适合读多写少
- `ConcurrentHashMap`：高并发 Map 首选

## 六、fail-fast 机制

很多集合在使用迭代器遍历时，如果集合结构被并发修改，可能抛出：

```java
ConcurrentModificationException
```

这叫做 **fail-fast** 机制。

注意：

- 它不是严格意义上的线程安全机制
- 只是“尽快失败、尽早提醒”的一种机制
- 常见于 `ArrayList`、`HashMap` 等集合

## 七、常见面试点总结

### 7.1 ArrayList 和 LinkedList 的区别

- `ArrayList`：底层是动态数组，随机访问快，适合读多写少
- `LinkedList`：底层是双向链表，头尾操作更方便，随机访问慢

### 7.2 HashMap 和 Hashtable 的区别

- `HashMap`：线程不安全，允许 `null` key/value
- `Hashtable`：线程安全，不允许 `null` key/value
- 现代开发中通常优先考虑 `HashMap` 或 `ConcurrentHashMap`

### 7.3 HashSet 为什么能去重

因为 `HashSet` 底层基于 `HashMap`，判重依赖：

- `hashCode()`
- `equals()`

### 7.4 TreeMap / TreeSet 为什么有序

因为底层是红黑树，元素或 key 会按照：

- 自然顺序
- 比较器顺序

进行维护。

### 7.5 为什么重写 equals 后通常也要重写 hashCode

因为在哈希集合中：

- 如果两个对象逻辑上相等，`equals()` 返回 `true`
- 那么它们的 `hashCode()` 也应该一致
- 否则会导致去重、查找等行为异常

### 7.6 栈为什么更推荐用 Deque

因为：

- `Stack` 是较老的类
- `Deque` 接口设计更现代
- `ArrayDeque` 在很多场景下性能更好

---

## 八、选型建议

- 频繁随机访问：`ArrayList`
- 频繁头尾插入删除：`LinkedList` 或 `ArrayDeque`
- 只想去重：`HashSet`
- 去重且保留插入顺序：`LinkedHashSet`
- 去重且自动排序：`TreeSet`
- 普通键值存储：`HashMap`
- 需要顺序：`LinkedHashMap`
- 需要排序和范围查询：`TreeMap`
- 高并发 Map：`ConcurrentHashMap`
- 栈 / 普通队列：优先考虑 `ArrayDeque`

---

## 九、一句话总结

- `List`：有序可重复
- `Set`：无重复
- `Queue`：按规则出队
- `Map`：存键值对
- 哈希类集合看 `hashCode() + equals()`
- 树类集合看 `compareTo() / Comparator`
- 不确定选什么时，`ArrayList`、`HashMap`、`ArrayDeque` 往往是最常见起点
